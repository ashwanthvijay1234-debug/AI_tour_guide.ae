Aim and Concept

What the project sets out to do, the problem it answers, and why that matters here.

Aim

To build a working Artificial Intelligence web application that solves a real problem for visitors to the United Arab Emirates, and to show how generative AI and Natural Language Processing can be applied to tourism — not as a chatbot bolted onto a page, but as the engine that produces the product itself.

Chosen Topic

Smart tourism. A generative UAE travel planner that writes a full day-by-day itinerary from four settings — destination, trip length, budget and interests — then lets the user refine it by talking to it in plain English.

Problem Statement

A printed guidebook cannot know who is reading it.

Not personal

A student on AED 2,000 and a honeymoon couple get the same 300 pages, and must filter it themselves.

Not flexible

A 44 °C afternoon or a tired toddler rewrites the day; the printed page cannot move to meet it.

Not current

Prices, opening hours and whole attractions change faster than editions are reprinted.

Not efficient

Comparing maps, prices and timings across seven emirates takes an evening — and still over-drives.

AI Solution Proposed

A four-stage pipeline. The code for every stage is in the appendix.

#StageWhat happens
01Understanding preferencesThe four settings become a natural-language brief. NLP reads what is implied as well as typed — “family” means shorter days and earlier evenings.
02Prompt engineeringA system instruction fixes the role, the currency, the pacing rules and the exact JSON shape. Constraining the output turns a chatty model into a reliable component.
03Generative reasoningGemini balances geography, timing and money token by token, writing a plan that did not exist before. Nothing is retrieved from a list of stored tours.
04Structured renderingThe reply is parsed back into data, drawn on screen, typeset into a PDF and plotted on a map.
Two modes, and the app always says which is running. With no API key an offline planner built into the JavaScript writes the itinerary, so the project works with no internet at all; with a key, Google Gemini writes it. A badge on every plan names the engine that produced it, so “is the AI actually running?” can always be answered.

Importance to UAE

  • Economy — tourism is a pillar of growth beyond oil, and a country that is easier to plan a trip to is easier to choose.
  • Sustainability — grouping each day's stops by area cuts driving, and with it fuel, emissions and time lost in traffic.
  • Culture — the model must include Emirati heritage in every plan, not only malls and towers.
  • Access — LLMs already work in Arabic, Hindi, Mandarin and Russian, so no separate edition need be printed.

This serves UAE Vision 2071 and the National AI Strategy 2031, which names tourism among the sectors AI should serve.

Reflection

What the build taught me, what went wrong on the way, and what I would take to the next project.

What I Learned

  • A language model becomes useful when you constrain it. Asked an open question it writes pleasant paragraphs. Pinned to a role, a currency, a pacing rule and an exact JSON shape, it becomes a component I can build a product on. Prompt engineering turned out to be the real engineering in this project.
  • Never trust a model's output format. Even when told “JSON only, no markdown fences”, it sometimes returns fences or a sentence first. The parser strips fences, retries on the widest {…} substring, and renders prose safely rather than failing.
  • Never trust model output as markup either. Every element is built with createElement and textContent, never innerHTML, so a stop title containing a script tag becomes a badly-named stop instead of running code.
  • Honesty has to be designed in. Both modes produce something that looks like an itinerary, so I added a provenance badge and a Test key button that makes one real request and reports the failure instead of hiding it.

Challenges Faced

ChallengeHow I solved it
Model IDs kept expiring I had hard-coded model names. Google retired them, every call returned 404, and the app silently fell back to the offline planner — with a valid key in the box. Now the app asks the API which models the key can really call and filters its preference list against that.
Errors blamed the wrong model The fallback chain reported the last error, so a bad key surfaced as “gemini-1.5-pro not found” — a model the user never picked. It now keeps the first error, from the model actually chosen.
The same plan every time Two causes. The counter seeding the shuffle reset on every page load, so a reload gave a byte-identical plan; it now persists. And the place pool was smaller than the trip needed, so every place was used every run — the pool grew to 103 real UAE locations.
“Cheaper” froze the plan Sorting by cost always picks the same cheapest stops. Adding a seeded jitter to the prices keeps the trip cheap while varying which cheap places are chosen.
Empty days on long trips A 14-day trip needs 84 stops and the pool holds fewer, so later days printed blank. The planner now cycles the pool instead, which is what a real fortnight looks like anyway.

Skills Developed

Technical

Semantic HTML, CSS custom properties and responsive layout, modern JavaScript with async/await, fetch and the DOM API.

AI

Prompt engineering, constraining output to a schema, temperature, model fallback chains, and reading an API's error responses properly.

Engineering

Debugging from symptoms, defensive coding, accessibility with ARIA, keeping secrets out of a repository, and version control with Git.

Conclusion

The project does what it set out to do: four answers become a complete, priced, mapped and printable UAE itinerary in under ten seconds, and the plan can be argued with in plain English afterwards. More importantly, it answers the question the subject is really about — what is AI actually good for?

Generative AI is most useful when it is given structure: a clear role, real constraints and a defined output. Left open-ended it writes nice paragraphs. Given a role, a currency, a pacing rule and an exact JSON shape, it becomes a reliable part of a working product — and that is the finding I would carry into the next build.
